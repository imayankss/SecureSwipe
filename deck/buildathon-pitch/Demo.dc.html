The walkthrough is built to be as convincing when it refuses.

1 Readiness probe Model provenance and bundle checksum are reported before any decision
2 Bounded decision One fixed fixture returns human_review or below_review_threshold — nothing else exists
3 Audit receipt A genuine chained hash is appended and shown — editing any past record breaks every hash after it
4 Idempotent replay The same request ID returns the same response with no duplicate event
5 Invalid request A malformed fixture is rejected 422 with no decision
6 Missing bundle Without a verified bundle the system fails closed and says which precondition failed

Steps 5 and 6 are the ones I would show first. A risk system that cannot refuse cleanly is not a risk system — and the deployed /demo is a clearly labelled recorded transcript, because there is no verified public scoring backend to pretend otherwise.
